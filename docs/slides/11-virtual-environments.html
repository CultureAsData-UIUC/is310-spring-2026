Virtual Environments & Python Packages

Managing Dependencies and External Libraries

The Problem

Different projects need different versions of libraries.

What if: - Project A needs version 1.0 of a library - Project B needs version 2.0 of the same library

This is called “dependency hell.” Installing one version breaks the other project. Virtual environments solve this by isolating dependencies per project.

Dependency Hell (xkcd Reference)

Every Python developer faces this eventually.

The Solution: Virtual Environments

A virtual environment is a self-contained directory containing: - A specific Python version - Project-specific packages - Isolated from other projects

Virtual environments are lightweight and can be created per project. They’re the industry standard way to manage Python dependencies.

pip: Python Installs Packages

pip is Python’s package manager.

First, check your version:

pip3 --version

pip comes with Python 3, but you may need to use pip3 if you have multiple Python versions installed.

Creating a Virtual Environment

Method 1: VS Code (Recommended)

Use Command Palette: Cmd+Shift+P (Mac) or Ctrl+Shift+P (Windows)

Type: Python: Create Environment

Select Venv

VS Code handles the details for you. It will create a .venv folder and automatically activate it when you open the terminal.

Creating a Virtual Environment

Method 2: Terminal

python3 -m venv is310-env

This creates a folder called is310-env.

This command tells Python to run the venv module and create an environment. You can name it anything, but descriptive names help you remember which project it’s for.

Activating a Virtual Environment

Mac/Linux:

source is310-env/bin/activate

Windows Command Prompt:

is310-env\Scripts\activate

Windows PowerShell:

.\is310-env\Scripts\Activate.ps1

Once activated, your terminal prompt will show the environment name in parentheses, like (is310-env). This tells you the environment is active.

Deactivating

deactivate

Run this when you’re done working to deactivate the environment. You’ll see the environment name disappear from your prompt.

Adding to .gitignore

Virtual environments should not be committed to git.

Add to .gitignore:

is310-env/
.venv/

Virtual environments are specific to your computer. If someone clones your repo, they’ll create their own environment. This is why we exclude them from version control.

Installing Packages

With your virtual environment activated, install packages using pip:

pip3 install rich

CRITICAL: Only run pip when your virtual environment is activated. This ensures the package installs in your isolated environment, not globally.

Verifying Installation

Check what’s installed:

pip list

Test in Python:

import rich
print(rich.__version__)

pip list shows all installed packages in the current virtual environment. Testing with import ensures everything worked correctly.

The Rich Library

Rich is a popular library for beautiful terminal output.

Created by Will McGugan and has 50,000+ GitHub stars.

It’s a great example of a modern, well-maintained Python library. You can see its GitHub repo at https://github.com/Textualize/rich.

Using Rich

from rich import print

print("Hello, [bold magenta]World[/bold magenta]!", ":vampire:")

Output:

Hello, World! 🧛

(with colored text)

Rich lets you format text with colors, styles, and emojis in the terminal. The syntax uses markup tags like HTML.

Rich Tables

from rich.table import Table
from rich.console import Console

console = Console()
table = Table(title="Movies")

table.add_column("Title", style="magenta")
table.add_column("Year", style="cyan")

table.add_row("The Matrix", "1999")
table.add_row("Star Wars", "1977")

console.print(table)

Rich provides classes like Table and Console for creating formatted output. This is much nicer than plain text for displaying data.

Rich with Data

from rich.console import Console

console = Console()
movies = [
    {"Title": "The Matrix", "Year": 1999},
    {"Title": "Star Wars", "Year": 1977}
]

for movie in movies:
    console.print(f"[bold]{movie['Title']}[/bold] ({movie['Year']})")

You can loop through data structures and use Rich to format each item. This is how you create beautiful CLI applications.

Building a CLI Application

Now you can build command-line tools that: 1. Display data beautifully (using Rich) 2. Get input from users 3. Save data to files 4. Handle errors gracefully

This is the foundation of real Python applications. You can build tools that are both functional and user-friendly.

A Simple CLI Workflow

  1. Show example data using Rich
  2. Ask user for input
  3. Validate and confirm data
  4. Save to file
  5. Print success message

This pattern—show examples, get input, validate, save—is common in data entry applications.

Putting It All Together

  • Virtual Environments: Keep projects isolated
  • pip: Install external packages
  • Rich: Create beautiful terminal output
  • File I/O: Save and load data

With these tools, you can create sophisticated Python applications that are maintainable and pleasant to use.
